# dsh-session-delete

Пункт **«Удалить сессию»** в меню сессии в сайдбаре [DeepSeek Harness](https://github.com/deepseek-ai):
проверка связанных сессий, подтверждение словом `delete` и опциональное удаление
файлов проекта, которые эта сессия создала.

Плагин личный, но устроен как обычный bundle DSH: ставится из интерфейса или
командой, удаляется одной кнопкой.

## Как это выглядит

У каждой строки сессии в меню «…» появляется пункт **«Удалить сессию»**.
Дальше три шага:

1. **«Вы точно хотите удалить данную сессию?»** — Да / Нет. «Нет» закрывает окно.
2. Если сессия **связана** с другими по линии родства (родительская или
   субагентские потомки), показывается предупреждение с раскрываемым списком:
   название, тип связи и пометка «активна». Ещё одно «Да» — только продолжение.
3. **Подтверждение:** нужно ввести слово `delete`, после чего становится доступна
   кнопка «Да». Здесь же — чекбокс «Также удалить файлы, созданные этой сессией
   (N)» с раскрываемым списком путей и предупреждением о необратимости.

## Что удаляется

- лог сессии на диске и логи её дочерних субагентских сессий;
- строка в кэше проекций;
- закрепление и архивная отметка;
- членство в workspace; если сессия была в нём последней, запись workspace
  исчезает из списка (папка проекта на диске при этом остаётся);
- **по чекбоксу** — существующие файлы проекта, которые сессия создала или
  изменила файловыми инструментами (`write`, `edit`, `apply_patch`,
  `str_replace_editor`); пути разрешаются только внутри рабочей папки сессии.

Открытая (живая) сессия сначала закрывается штатным завершением агента DSH:
отмена текущего хода, сброс лога на диск, закрытие write-хендла, отсоединение от
живых хранилищ. Только после этого удаляются данные. Если закрыть сессию не
удалось, удаление отменяется и ничего не трогается.

## Чего плагин не делает

- не удаляет папку workspace и файлы, созданные через `bash`/`pwsh` или
  скриптами: DSH не хранит durable-список таких изменений;
- не считает форки «связанными»: durable-связи с источником у них нет;
- не удаляет вложения из общей медиатеки (`~/.dsh/cache/attachments`).

## Языки

Все тексты берутся из локали DSH и переключаются вместе с языком в настройках:
`en`, `ru`, `de`, `es`, `fr`, `ja`, `pt`, `zh`. Метаданные плагина в Plugin
Manager локализованы так же.

## Установка

```
dsh plugin --profile desktop add github:mikhailnarzik-source/dsh-session-delete
```

После установки перезапустите DSH.

## Как устроено

| Файл | Роль |
|---|---|
| `index.js` | Host: два маршрута на аутентифицированном `/api` (`inspect` и `delete`), закрытие живого агента, чтение лога, удаление артефактов и файлов проекта |
| `client.js` | Браузерная половина: пункт меню в `sidebar.workspaces.session.menu.item` и диалог в `shell.overlay`; копия примитивов DSH под префиксом `dshsd-`, тема и шрифт наследуются |
| `cordis.patch.yml` | Вставка строки плагина в профиль |
| `locale/*.json` | Название и описание для Plugin Manager |

Маршруты доступны только owner-peer'у страницы (общая авторизация `/api`), а
`delete` дополнительно требует литерал `delete` в теле запроса. Файлы
удаляются только внутри рабочей папки сессии и только те, что существуют на
момент подтверждения.
